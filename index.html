GOOGLE DRIVE ACCESS / 谷歌云端硬盘权限

Why the full Drive scope is requested

为什么申请完整 Drive 权限

The Collector runs unattended as a Cloud Run Job and writes into an existing, user-owned Drive folder. Because there is no interactive Google Picker during a scheduled run, it requests https://www.googleapis.com/auth/drive.

Important: this OAuth scope can technically view and manage all files in the authorizing account. The Collector's implemented behavior is narrower: it lists children under the configured root, creates dated batch folders, uploads or updates named JSON files, reads back those files for integrity checks, and restores the prior source-state file referenced by its own pointer. It does not delete Drive files.

Collector 以无人值守的 Cloud Run Job 运行，并写入用户已有的 Drive 文件夹。完整 Drive scope 在权限层面可查看和管理授权账户中的全部文件；但程序实际操作被限定在配置的根目录、其批次子目录，以及自身 pointer 引用的文件。程序不会删除 Drive 文件。

OPERATING GUARDRAILS

The pointer moves only after the evidence survives a round trip.

Immutable batches

Each run receives its own dated folder and run identifier, preventing consumers from mixing old and new artifacts.

Independent readback

Every uploaded artifact is downloaded again. Its digest and byte count must match before publication succeeds.

Secrets stay secret

OAuth credentials are stored in Google Secret Manager and injected only into the runtime job. They are not published on this site or committed to source control.

Revocable by the owner

The owner can revoke the OAuth grant, delete the stored secrets, remove generated Drive files, or shut down the Cloud project at any time.

TRANSPARENT BY DESIGN

No advertising. No sale of Google user data. No AI training on Drive data.
